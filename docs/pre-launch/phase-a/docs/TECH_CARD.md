# Meduzellar Pre-Launch TECH_CARD

**Document state** Draft · **Reviewed against published provider information** 2026-11-26

`Approved` applies only to the explicit owner boundary below. `Proposed` identifies the recommendation for Phase A review. `Candidate` identifies an alternative or a conditional dependency. Choose exact patched versions at sign-off after checking security advisories, support windows and the dependency matrix.

| Decision | State | Recommendation and rationale | Alternatives and tradeoff |
| --- | --- | --- | --- |
| PL-D01 boundary | Approved | Dedicated `meduzellar-pre-launch`, Size A, isolated modular monolith direction and independent governance/deployment. | In-tree and nested workspace were evaluated at the governance gate. |
| PL-D02 runtime and tooling | Proposed | Node.js 24 LTS, strict TypeScript, npm with committed lockfile, ESLint and Prettier. Pin Node in CI and target 24.x on Vercel. | pnpm offers good workspace ergonomics. A single application benefits from fewer tools; the Platform package manager has independent authority. |
| PL-D03 full-stack web | Proposed | Active LTS Next.js 16 App Router, supported React peer, server-rendered public pages and Node.js Route Handlers for JSON and callbacks. One deployable and same-origin form. | Astro plus API adapter fits the page, with additional integration for admin and jobs. A separate Nest API increases deployable count. |
| PL-D04 styling and validation | Proposed | CSS variables, CSS Modules, semantic HTML and local state. Zod for server schemas and shared safe shape validation. | Tailwind is viable, but CSS owns the tightly art-directed layout and few screens. Add utility tooling only with a concrete need. |
| PL-D05 assets and motion | Proposed | Responsive AVIF/WebP, layered CSS and licensed SVG icons. Use pre-rendered 3D artwork with CSS-styled semantic text, reduced motion and browser visibility control. | Motion library is a candidate for complex UI choreography. Three.js/R3F are candidates after source assets, owner review and a measured unmet visual requirement. |
| PL-D06 data | Proposed | Independent Neon Postgres 17 project for production, Prisma ORM 7 with `pg` adapter, pooled runtime and direct migration endpoint. Use parameterized SQL where locking requires it. | Supabase Postgres is credible if region or bundled identity favors it. Drizzle is smaller and SQL-centric; Prisma provides typed CRUD and migrations. Confirm supported adapter/pool transaction behavior in staging. Prisma 8 RC is deferred. |
| PL-D07 mail | Proposed | Resend individual Emails API for verification, confirmation and the consented launch message, retaining application control of eligibility, cancellation, per-recipient status and idempotency. Verify team limits, custom DKIM coverage and per-message unsubscribe handling. | Resend Broadcasts add provider contact synchronization and weaken app control after handoff. SES is a cheaper-volume candidate with production access, event plumbing and a different reconciliation contract. |
| PL-D08 durable scheduling | Proposed | Postgres transactional outbox, bounded batch processor and Vercel Pro minute cron. Database leases and retry state survive process termination. Prioritize verification and reserve capacity for it. | Render scheduled process carries the same DB contract. An external queue, Redis and BullMQ add cost and operational state without a demonstrated need. |
| PL-D09 admin | Proposed | Clerk Pro invite-only operator sign-in with mandatory MFA, local immutable-subject grants, strict fresh second-factor evidence for campaign and privacy mutations. Separate Clerk environments. | Managed enterprise IdP with explicit MFA claims is viable. Better Auth reduces vendor spend and adds session, account recovery and MFA lifecycle ownership. Block sensitive actions if Clerk cannot produce trustworthy freshness data. |
| PL-D10 abuse and security | Proposed | Turnstile with server Siteverify, edge limits and shared Postgres rate counters. App-level auth, CSRF, exact origin policy, CSP, signing, and PII-safe telemetry. | DB limits alone save one integration but absorb more bot traffic. Never fall back to unlimited registration on dependency failure. |
| PL-D11 tests | Proposed | Vitest for policy/contract and integration suites, test Postgres for constraints and scheduler races, Playwright for browsers, screenshots and axe checks. | Node test runner is adequate for pure unit tests. Playwright covers visual and multi-browser behavior in the same harness. |
| PL-D12 deployment | Proposed | Vercel Pro, one region colocated with Neon, one project each for staging and production, versioned static assets, GitHub Actions subject to activation approval. | Render Node service and cron offer portability and potentially lower hosting cost. Confirm post-start routing, CDN/image performance, resource size and region before substitution. |
| PL-D13 observability | Proposed | Structured platform logs, DB operational counts, independent page/worker-heartbeat monitoring and alerting. Disable tracking pixels and link rewriting on token mail. | A hosted exception tool or log drain is optional for incident needs beyond bundled retention. |

Compatibility research covers Next.js support and Node hosting, the Prisma 7 adapters, and Clerk's MFA configuration. Clerk's reverification helpers can downgrade when a factor is unavailable. The proposed server check requires actual recent second-factor evidence and has a dedicated fail-closed test. [Next.js support](https://nextjs.org/support-policy) · [Vercel Node versions](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions) · [Prisma 7 drivers](https://docs.prisma.io/docs/orm/v7/core-concepts/supported-databases/database-drivers) · [Clerk MFA](https://clerk.com/docs/guides/configure/auth-strategies/sign-up-sign-in-options) · [Clerk reverification](https://clerk.com/docs/guides/secure/reverification)

Resend documents direct sends with consent and one-click unsubscribe requirements. CDN, cron plan and throughput constraints inform the outbox sizing. [Resend plan FAQ](https://resend.com/pricing?product=transactional) · [Usage limits](https://resend.com/docs/api-reference/rate-limit) · [Vercel cron](https://vercel.com/docs/schedules/cron-jobs/usage-and-pricing)
